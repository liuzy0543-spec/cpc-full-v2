## 1. 为什么不能用 demo 数据做排名

本机演示数据实测：

```
CellProfiler 输出: Cells.csv 4 行, Nuclei.csv 4 行, Image.csv 2 行
即 4 个细胞、2 个孔、0 个处理标签
```

**4 个样本、2 个标签**，无法支撑任何方法排名——任何排序都会是噪声。

因此改用**可控合成基准**：细胞由已知因子生成，因此"正确答案"是确定的。
这是在没有标签数据时唯一能打分的方式。

---

## 2. 只有 2 个方法可以公平比较

| 方法 | 权重来源 | 能否公平评估 |
|---|---|---|
| `deepprofiler` | 官方 CP CNN v1（Cell Painting 训练） | ✅ |
| `ca_mae` | 官方 OpenPhenom-S/16（Cell Painting 训练） | ✅ |
| `cellclip` | 官方权重**但需要逐通道 DINOv2-Giant 向量** | ❌ 我们没有那些向量，喂什么都是伪造的 |
| `o2vae` | **本项目自训 50 epoch 于 o2-mnist 手写数字** | ❌ 不是细胞模型 |

把 `cellclip`/`o2vae` 拉进排名，等于给方法喂假输入、或拿数字模型比细胞模型。

**分辨率也按各自原生给**：CA-MAE 要 256×256、DeepProfiler 要 32×32 裁剪。
在 256 渲染、对 DeepProfiler 下采样——避免一方吃另一方的 4× 上采样。

## 3. 实测结果

### 3.1 主表（3 个 seed 的均值；64 细胞/seed）

| 方法 | kNN 核大小 | kNN 线粒体 | \|rho\| 核 | \|rho\| 线粒体 | 有效秩 | nuisance |
|---|---|---|---|---|---|---|
| `deepprofiler` | 0.865 | 0.667 | 0.864 | 0.606 | 4.50 | **0.000** |
| `ca_mae` | 0.865 | **0.786** | **0.973** | **0.711** | **1.34** | 0.213 |
| 原始像素 32×32 | **0.927** | 0.422 | **0.974** | 0.442 | 4.52 | — |
| 原始像素 256→32 | **0.948** | 0.370 | 0.962 | 0.407 | 4.49 | — |
| 随机投影（对照） | 0.307 | 0.297 | 0.319 | 0.278 | 57.55 | — |

> kNN 随机基线 = 0.333。随机投影实测 0.307/0.297 ⇒ **指标已校准**，不是虚高。

### 3.2 ★ 最重要的发现：原始像素赢了一半

| 因子 | 谁更好 |
|---|---|
| 核大小（nucleus_size） | **原始像素 0.927–0.948 > 两个嵌入 0.865** |
| 线粒体碎片化（mito_fragmentation） | **嵌入 0.667 / 0.786 ≫ 原始像素 0.370–0.422** |

**含义**：合成细胞是高斯团块，"核的大小"用像素面积就能直接读出来，
所以这个因子**不具区分力**；而"线粒体碎片化"是多个小斑点的空间分布，
像素特征抓不住，嵌入明显更强。

**这正好说明：合成基准里有一半因子是"伪任务"**，
用它排名会把"擅长简单几何量"当成"方法更好"。

### 3.3 两个方法的强弱是互补的，不是压倒性的

| 指标 | 赢家 |
|---|---|
| kNN 核大小 | 平（0.865 / 0.865） |
| kNN 线粒体碎片化 | **ca_mae**（0.786 vs 0.667） |
| \|rho\| 核 / 线粒体 | **ca_mae**（0.973/0.711 vs 0.864/0.606） |
| nuisance 不变量 | **deepprofiler**（0.000 vs 0.213） |

**但 `deepprofiler` 的 nuisance=0.000 不是学出来的，而是构造使然**：
它的裁剪图做 per-crop min-max，把"整体曝光"这个自由度**在数学上消掉了**。
拿它当"鲁棒性更强"的证据是不公平的——那是归一化送的。

### 3.4 `ca_mae` 的有效秩只有 1.34

384 维嵌入在 64 个样本上有效秩 **1.34**，即几乎坍缩到一维；
`deepprofiler` 是 4.50。这是**值得注意的现象**，但我不能断定是缺陷：
合成高斯团块对 OpenPhenom 是**分布外输入**，实例归一化可能因此饱和。
**需要真实细胞数据才能判断这是不是真问题。**

### 3.5 排名与稳定性

```
score = mean(kNN 归一化, |rho|, 1/(1+nuisance))

1. ca_mae        0.8015  (kNN=0.738 rho=0.842 invariance=0.824)
2. deepprofiler  0.7943  (kNN=0.648 rho=0.735 invariance=1.000)

score gap = 0.0071  -> SMALL: 按打平处理，不宣布赢家
```

3 个 seed 的 sd：kNN 0.03–0.04，\|rho\| 0.11–0.13。
**方法间差距（0.007）远小于 seed 波动**，所以排序不可靠。

**另外，这个 composite score 的权重是我定的，本身是任意选择。**
换成"只看线粒体因子"就 ca_mae 赢；换成"只奖励 nuisance 不变量"就 deepprofiler 赢。
**一个换权重就翻转的排名，不是结论。**

## 4. 要真正回答"哪个更好"，缺什么

| 缺口 | 说明 |
|---|---|
| **带处理标签的真实数据** | 标准做法是用 JUMP Cell Painting：同孔重复 + 已知扰动，算 mean average precision / 孔级重复相关性 |
| **每方法 ≥ 数百细胞** | 本基准 64 个，sd 已经接近方法间差距 |
| **原生分辨率裁剪** | CA-MAE 要 256×256 的真实单细胞裁剪，本机原始视野只有 64×64 |
| **CellCLIP 的 DINOv2 向量** | 需要跑 DINOv2-Giant 预处理，否则它无法参与 |
| **o2vae 的细胞权重** | 现有权重是手写数字，与细胞无关 |

**结论**：harness 已就绪（`embedding_benchmark.py` + 本脚本），
数据一到位就能直接跑出有意义的排名。**但用现有数据排名是不诚实的。**

## 5. 本轮顺带修掉的两个真缺陷

### 5.1 `embed()` 每次调用都重载权重

实测同一方法连续两次调用：

```
修复前: call1 7.04 s, call2 ~7 s       ← 每次都重建 adapter、重载 712 MB
修复后: call1 8.79 s, call2 0.032 s    ← 第二次命中缓存
```

对一个"要嵌入整个数据集"的基准来说，这不是慢，是**不可用**。
已加 adapter 缓存（键 = 方法名 + 权重 sha256），并提供 `models.clear_adapter_cache()`。
验证：两次调用结果 `identical=True`（**缓存不改变数值**）。

### 5.2 `o2vae` 在 CUDA 上直接崩

```
device=cpu   OK shape=(2, 64)
device=cuda  FAIL RuntimeError: Expected all tensors to be on the same device,
             but found at least two devices, cuda:0 and cpu!
```

原因：e2cnn 把可操控卷积的基张量存成普通属性而非注册 buffer，`model.to()` 移不动它。
而 `select_device()` 在 GPU 可用时**默认选 CUDA**——即默认路径是坏的。

修法：自动选择时回落到 CPU；只有显式 `device='cuda'` 才报错（那时调用方已指定了做不到的事）。

指标定义（脚本内可查）：
- `knn_accuracy`：留一法 k=5，对因子三分位分类；随机=0.333
- `best_pc_spearman`：因子与最相关主成分的 |Spearman|
- `effective_rank`：奇异值谱的参与比（1 = 完全坍缩）
- `nuisance`：同细胞仅改曝光后的嵌入位移 / 跨细胞离散度（越低越稳）
